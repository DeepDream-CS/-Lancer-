## 用户确认的解释

- 每个牌照独立取得并分别计费。先遣兵 I、守夜人 II、霸主 III 同时取得时合计 6 级牌照；每个牌照仅解锁自己的装备。
- 二、三级专业牌照分别需要同厂商至少一、二级普通牌照，或其指定前级专业牌照。专业牌照不会解锁普通骨架。
- 可记录其中作为 GM 额外奖励的等级；额外奖励不提高角色 LL、毅力、天赋或核心奖励数量，但计入厂商牌照资格合计。
- 运动驱动器的线性场：目标每点装甲增加 1d6 额外伤害，最多 3d6。
- 密特拉协定：支付 1 热度选一项，支付 3 热度从三项中任选两项。

## 配装支持

- 模块化先进战斗步枪可选择打印数据，安装最多两个不同模组；每个模组成本减 1 SP，最低 1 SP。模组限制、独特装备限制、AI 数量与 SP 检查包含第二模组。
- 战术带占据一个非内置挂载点。最多指定两个已安装且带榴弹、地雷或可展开标签的系统，其合计 SP 成本减 4，最低 0；与“招牌动作”叠用时不会将同一系统成本减到负数。
- 哨兵无人机可记录部署时使用的已安装非超重型 CQB／步枪。
- 武器舱可记录一件主武器或两件副武器，并与合法非内置挂载点交换。舱内武器不列入可用攻击武器；交换后检查挂载规格、SP 和独特装备。带模组的武器先移除模组再交换，模块化步枪的打印数据随武器保存。
- 动作、反应、热度、状态及条件伤害展示规则，由游戏中的参与者按场上情况结算。
- JSON 保存全部专业牌照和配置；驾驶员图片列出专业牌照；文字与机甲图片导出包含第二模组及特殊系统配置。

## 查询与核验补充（2026-11-04）

专业牌照武器可在武器表查询，系统和武器改装可在系统库查询；来源及「当前可用」筛选按当前角色判断。查询面板展示基础数据，不会自动安装或交换装备。工程等加成后的受限次数在实际配装与导出中查看。

独立 Git 仓库或历史工作副本不属于正式数据来源；继续修改本项目的 `source/expansions/professional-licenses.js`。完整截图仍在 `source/expansions/references/professional/`，移动说明文档不影响其位置。涉及模块或风味展示时，除规则检查外，补跑 `node tools/test-mod-display.js`、`node tools/test-equipment-lore.js`；系统库交互使用 `node tools/test-system-library.js` 检查。

## PI-OF 补录

三张牌照采用用户提供的自定义装备规则与确认后的风味文本，前置依次为拓荒者、星际矿工。铆钉仅允许目标自己以快速动作拔出；天候塔雷暴的科技攻击难度只影响敌对角色。动作、地形改变、维修、临时固定和热度由参与者按场上情况结算。原始材料为用户文本，未设置截图链接。

## K/KCA 补录

采用用户确认的自定义规则及风味文本，前置依次为侍从、骑士。短剑招架反击使用同挂载点的另一件近战武器；重骑枪冲刺只能作为标准移动或推进的一部分，不需要额外动作，命中后到下次全面维修前不可使用或修复。宣战为快速动作。守护铠依次移动、获得护盾、承受伤害，无法到达盟友邻近自由空间时不能反应。凯旋消耗次数计入工程等加成。条件攻击、移动、场景次数、临时加值与状态按场上情况结算；不将条件效果计入常驻数值。

## 装备风味与格式（2026-11-05）

PI-OF 与 K/KCA 新增的四件武器、八件系统已补齐用户确认的独立风味文本，标明自定义来源，不附虚构 PDF 页码。装备效果采用统一动作框、触发和条件标识、规则分行及频率强调；重复动作说明合并，数值、动作类型和限制保留。
