# Foundry 内容包

[返回文档目录](README.md)

更新日期：2026-11-14。

车卡器的内容可以带进 Foundry VTT 的「LANCER」系统，不需要修改系统本体。由三部分组成：

| 部分 | 文件 | 作用 | 当前版本 |
|---|---|---|---|
| 核心规则书内容包（中文） | `dist/fvtt/lancer-cn-core.lcp` | 核心骨架、武器、系统、改装、核心奖励、天赋、驾驶员装备、技能、标签、状态与状况，以及核心规则书的 NPC 职业、模板与特性；覆盖 Foundry 核心数据的英文版 | 1.1.0 |
| 扩展内容包（中文） | `dist/fvtt/lancer-cn-expansions.lcp` | 车卡器收录的扩展内容、官方补充书 NPC 模板与特性、官方模组与第三方书的 NPC 职业 / 模板 / 特性；与官方补充书相同的条目覆盖英文版，其余为新增 | 1.6.0 |
| 界面中文模组 lancer-cn | `dist/fvtt/lancer-cn/`（`dist/fvtt/lancer-cn.zip`） | 系统界面中文、骨架插图、专业牌照与扩展厂商资料，以及攻击时选目标、机甲核心协议（CP）全骨架自动化、武器与改装特效、科技与入侵单选项隔离、全部 50 项驾驶员天赋与战斗核心奖励自动化、自动挂异常与撤销、一键豁免检定与减半联动、非攻击卡掷伤害与范围模板、跨权限护甲抗性结算与预览、回合结束清异常提醒、掩护区、困难与危险地形、六边形墙体、导入车卡器战斗地图、指示物名字与飘字、机甲/NPC/驾驶员基础动作与对抗检定、受限计数、可点击的骰子等战斗工具 | 1.13.0 |

车卡器还有三个导出：「角色卡」页的「导出到 Foundry」，把角色导出为 Foundry 驾驶员表可以读入的 JSON（见[从车卡器导入角色](#从车卡器导入角色)）；顶部「NPC 构筑」把 NPC 导出为 Foundry 的 NPC 角色数据（见[从车卡器导入 NPC](#从车卡器导入-npc)）；「⑤ 战斗地图」页的「导出到 Foundry」把六角格战斗地图导出为 Foundry 场景 JSON（见[从车卡器导入战斗地图](#从车卡器导入战斗地图)）。

`dist/fvtt/lancer-cn-bundle.zip` 是本机测试用的打包（模组文件夹 + 两个内容包 + 安装说明），不是正式发布物。

## 安装与导入

### 环境要求

- Foundry VTT **v13**，LANCER 系统 **v3.1.3**。LANCER 3.1.3 只支持 Foundry v13（`maximum: 13`），Foundry v14 无法安装该系统。
- Foundry 核心界面（侧栏、设置、菜单）的中文需要另装 fvtt-cn 的 foundry_chn。它的最新版只适用于 v14，v13 要用 13.350：`https://github.com/fvtt-cn/foundry_chn/releases/download/13.350/module.json`。

### 安装模组

两种方式任选：

- **清单链接**（需先推送，GitHub Pages 更新后可用）：在 Foundry「附加模组 → 安装模组」底部的清单链接填入 `https://deepdream-cs.github.io/-Lancer-/dist/fvtt/lancer-cn/module.json`。
- **手动放置**：把 `dist/fvtt/lancer-cn` 整个文件夹放进 Foundry 用户数据的 `Data/modules/`，得到 `Data/modules/lancer-cn/module.json`（不能多套一层文件夹）。

装好后在世界的「管理模组」中启用「LANCER 中文」，再到「配置设置 → 核心 → 语言」选「中文」。语言是每个浏览器各自的设置，玩家也要各自切换。模组更新后要**重启 Foundry**（新增模组设置、区域行为类型或 socket 时，只刷新页面不会生效）。

### 导入内容包（GM）

在侧栏「合集包」标签打开 LANCER 内容包管理器（LANCER Compendium Manager）：

1. 更新 / 建立核心数据，勾选要用的官方补充书（Long Rim、Wallflower、KTB、Dustgrave、OSR、OWS、SotW、SSMR）后导入。
2. 「从文件导入」`lancer-cn-core.lcp`。
3. 「从文件导入」`lancer-cn-expansions.lcp`。
4. 在「配置设置 → 模组设置 → LANCER 中文」点「导入车卡器资料」：建立专业牌照、把骨架牌照改为中文名，并生成「车卡器资料」日志。

顺序很重要：Foundry 按条目 id 覆盖已有条目，中文包必须在英文数据**之后**导入。内容包管理器每次导入都把该包移到已导入列表的末尾，列表顺序就是最近一次导入顺序。以后如果重新导入英文核心数据或官方补充书（例如系统升级后提示更新），对应条目会变回英文，要再导入一次中文包。

先导入英文数据还有一个好处：覆盖已有骨架时 Foundry 不改条目图片，骨架保留 Foundry 自带的 Retrograde Minis 插图。

角色身上的物品是导入时从合集包复制的副本。内容包更新后，已有角色要重新导入角色 JSON（或重新拖入物品），才会用上新内容。

两个中文包也带有 NPC 职业、模板与特性，导入后在「NPC 职业」「NPC 模板」「NPC 特性」合集包里；导入职业时，系统会照例在 NPC 合集包里为每个职业建一个同名 NPC（见[内容包的内容 · NPC](#npc)）。

### 常见问题

实际导入时遇到过的情况：

| 现象 | 原因 | 处理 |
|---|---|---|
| 导入扩展包时报「LancerActor validation errors: system: stats: edef: must be an integer」 | 部署物的回避、电子防御写成了「与部署者相同」或空白，Foundry 部署物的这些数值必须是整数 | 已在构建时修正（见[检查范围](#检查范围)）；用新版扩展包重新导入 |
| 装了模组，界面仍是英文 | 界面语言还是 English | 在「配置设置 → 核心 → 语言」选「中文」。可在控制台运行 `game.i18n.lang` 确认，应为 `"cn"` |
| 扩展条目是中文，核心条目（如观察员、埃弗勒斯）变回英文 | 中文核心包之后又导入了英文核心数据 | 重新导入 `lancer-cn-core.lcp`，再导入一次车卡器资料，并重新导入角色 JSON |
| 侧栏、设置等 Foundry 自己的界面是英文 | 本模组只翻译 LANCER 系统的部分 | 另装 foundry_chn 13.350 |
| 区域行为列表里没有「LANCER 掩护区」、工具栏没有新工具、模组设置里没有新选项 | 模组更新后没有重启 | 重启 Foundry |
| 用六边形墙体拖动时多出一道直线墙；删墙后留下删不掉的深色六边形 | 模组 1.4.0 的问题 | 更新到 1.4.1 以上；留下的六边形用「六边形墙体」工具点一下即可删除 |
| 伤害面板目标名两侧是方框、数值框被挤成「1(」 | 模组 1.5.0 以前的中文版面问题 | 更新到 1.5.1 以上 |
| 施加伤害、热度后指示物上没有飘字 | LANCER 的「浮动伤害数字」是每位玩家各自的设置，默认关闭 | 模组 1.6.0 起在每个客户端第一次载入时打开一次；之后被关掉的话，在「配置设置 → 系统设置」重新勾选「浮动伤害数字」 |

## 从车卡器导入角色

车卡器「角色卡」页的「导出到 Foundry」生成 COMP/CON v2 格式的驾驶员 JSON（`assets/js/foundry-export.js`）。在 Foundry 中新建一个驾驶员角色，打开驾驶员表的 <RM-4://同步> 页，在「文件导入」中选择这个文件；系统会建立技能触发、天赋、牌照、核心奖励、驾驶员装备，并新建机甲（骨架、挂载武器与改装、系统、内建武器）。

- 需要先导入两个中文内容包；专业牌照需要先运行模组的「导入车卡器资料」，否则这些牌照会列在导入结果的缺失清单里。新建机甲需要 GM 权限或 GM 允许玩家创建角色。
- 与官方补充书重复的扩展条目按 `source/fvtt/official-map.json`（构建时写入 `data.js` 的 `fvtt_map`）改用官方 id。
- 技能触发的 +2 / +4 / +6 换成等级 1–3；车卡器自定义触发导出为自定义技能。机甲 HP、结构、压力、维修按车卡器的计算填满；受限装备的次数包含工程等加成。
- Foundry 没有对应字段的配置写进机甲备注「【车卡器配置】」：第二改装、选用的数据组、武器舱、战术带、哨兵无人机武器、招牌动作 / 超功率口径 / 自动稳定指定的对象、康格多遗产特征。自定义专业牌照和额外牌照等级写进驾驶员经历。
- 重复导入同一角色时，机甲按「驾驶员 id + 序号」匹配并更新，驾驶员身上的物品会先清空再重建（Foundry 导入的原有做法）。

`node tools/test-foundry-export.js` 检查导出结构符合 foundryvtt-lancer 3.1.3 的 `importCCv2`，并对所有 103 个骨架导出，确认每个条目 id 都能在中文内容包或 Foundry 自带数据中找到。

## 从车卡器导入 NPC

车卡器顶部「NPC 构筑」的「导出到 Foundry」生成 LANCER 系统的 NPC 角色数据（`assets/js/npc-builder.js` 的 `toFoundry`），不依赖内容包或模组。

导入方法：

1. 在 Foundry 的角色目录新建一个角色，类型选 **NPC**。
2. 在目录里右键这个角色，选「导入数据」（Import Data），再选择导出的文件。

导入的内容：

- 职业：三个层级的完整数值。
- 已选的模板。
- 全部特性，包括基础、已选的可选项和从其他职业添加的。

具体处理：

- 角色层级取车卡器中的层级。在角色表上切换层级后，数值、攻击加值、伤害、按层级的标签值（如可靠 2/3/4）会跟着变。
- 模板的数值加成导出为特性的加成（bonus）或覆盖（override），由 Foundry 自动计入。车卡器里的手动加减导出为一个「车卡器手动调整」特征。
- 效果文字保留原书「x/y/z」的写法，不替换成某一层级的值。
- 受限特性的次数按当前层级填好。
- 指示物默认为敌对，并按大小设置尺寸。

`node tools/test-npc-builder.js` 对每个职业的每个层级（勾选全部可选项），以及每个模板（勾选全部可选项）都做一次导出。导出结果按 foundryvtt-lancer 3.1.3 的 NPC 数据模型检查：

- 特性、伤害、射程、科技类型的枚举值；
- 整数字段，以及大小至少 1/2；
- 标签 id 存在，层级标签值用 `{a/b/c}` 格式；
- 物品 `_id` 为 16 位。

导出用的职业、模板与特性 id 与两个中文内容包里的 NPC 条目相同（见[内容包的内容 · NPC](#npc)）。导入数据不需要先导入内容包，但导入后在合集包里也能找到同一套职业与模板，供手动构筑 NPC 时使用。

## 从车卡器导入战斗地图

车卡器「⑤ 战斗地图」页的「导出到 Foundry」生成 Foundry v13 场景 JSON（`assets/js/battlemap.js` 的 `BattleMap.toFoundry`），同时在 `flags["lancer-cn"].battlemap` 保留裁剪后的原始地图数据（车卡器的「导入地图」也能读回该文件）。支持两种导入工作流：

1. **模组一键导入（推荐）**：启用 `lancer-cn` 1.9.0+ 后，GM 在侧栏「场景」顶部点**「导入车卡器地图」**（或「模组设置 → LANCER 中文 → 导入车卡器地图」），同时支持车卡器「导出地图」备份（`Lancer-战斗地图.json`）与「导出到 Foundry」文件（`*-foundry.json`）：
   - **新建独立六角格场景**：按车卡器当前可见范围新建平顶六角格场景（`padding: 0`、关闭迷雾与指示物视野、开启全局照明），并自动切换到该场景。
   - **铺到当前场景**：保留当前场景的背景底图、光照与已有指示物，对齐当前场景的六角网格写入地形与标记；重复导入默认自动替换此前导入过的车卡器地形与标记，场景里原有的手动掩护格会合并保留。
2. **Foundry 原生导入**：在 Foundry 场景目录新建一个场景，右键该场景选「导入数据」（Import Data），选择车卡器导出的 `*-foundry.json`（软/硬掩护区与危险地形区的自动化需要启用 `lancer-cn` 模组）。

地形与元素对应关系：

- **网格与列奇偶**：只导出当前可见范围 `[minQ..minQ+w-1] × [minR..minR+h-1]`。`minQ` 为偶数时设为 `HEXODDQ`（type=4，奇数列下移），`minQ` 为奇数（如向左扩展 3 列后）时设为 `HEXEVENQ`（type=5，偶数列下移）；铺到已有 `HEXODDQ` / `HEXEVENQ` 场景且列错位相反时，自动水平偏移 1 列以保持相邻格几何关系完全一致。
- **障碍物**：按模组 `hexWall` 格式生成沿格边的 6 段阻挡移动墙体 + 锁定的深色实心六边形图形（弹窗可勾选是否同时阻挡视线与光照）。
- **软性掩护 / 硬性掩护 / 困难地形 / 危险地形**：生成所有人可见的六边形区域（`Region`），导入后仍可用左侧「区域」工具栏的四把涂画工具逐格增删。
- **涂色格、文字标注与画线**：非默认底色的空地与「自定义」格导出为锁定的半透明六边形底层色块；格子标注导出为居中文字图形（不会把掩护/地形名重复印成文字）；画线导出为同色锁定折线。
- **单位 → 部署位置标记**：不生成没有 Actor 的空白指示物（否则攻击与目标面板会报错），改为可选导出底层的圆圈 + 名称/尺寸图形（大小 2/3/4 另带半透明占格轮廓）。GM 摆好真正的机甲与 NPC 指示物后，可在「导入车卡器地图」弹窗点**「清除部署标记」**一键删掉这些标记图形。

## 界面中文模组（lancer-cn）

### 界面翻译

- 语言文件中的 427 条（角色表、聊天卡、设置、状态图标名、结构 / 过热表等）译文在 `source/fvtt/module/cn-flat.json`，键与系统语言文件路径相同；`system-en.json` 是系统 v3.1.3 英文语言文件的快照，用于核对键和占位符。系统升级后替换该快照，构建会列出新增或删除的键。
- 语言代码为 `cn`，与 foundry_chn 相同，两者可同时使用。
- 术语与车卡器一致；结构 / 过热表的文字依 v3.5 第 75–76 页（例如炉心熔解可用自由动作重试工程检定，与 Foundry 英文的完整动作不同）。

### 写死的英文

系统模板、Svelte 界面和代码里还有约 680 段不经语言文件的英文（机甲 / 物品表的栏目名、挂载点选项、命中与伤害面板、掩护与命中选项、扫描卡、提示消息、对话框和聊天卡标题等）。模组不改系统本体，而是在界面语言为中文时，按词典把显示出来的文字换成中文：

- 只改文字节点和 `title`、`placeholder`、`data-tooltip`、`aria-label`、`alt` 属性；输入框的值、文本框、富文本编辑区、日志正文、侧栏文档列表不动，存档数据也不会改。之后新出现或被更新的文字（聊天消息、通知、命中面板里的勾选项）同样会翻译。
- 画布上的浮动数字（「-5 HP」「+2 热度」）通过包装系统调用的 `createScrollingText` 翻译。
- 词典在 `source/fvtt/module/`：
  - `cn-hardcoded.json` 的 `text`：英文 → 译文；含 `{x}` 的是句式，`{x}` 依次代入原文对应部分（可用 `{1}`、`{2}` 调换顺序），代入的部分若是枚举词也会翻译。值为 `null` 表示有意保留英文（快捷栏拖放、按钮数据缺失这类开发调试信息，以及教程示例中的呼号）；原文被 HTML 标签拆成几段时用 `{ "pieces": {...} }` 分段翻译。
  - `cn-hardcoded.json` 的 `context`：只在特定界面使用的译法，例如扫描卡里的 Armor 是「装甲」数值，物品栏分类里是「护甲」。
  - `cn-words.json`：尺寸、武器 / 伤害 / 射程类型、动作等枚举词（不分大小写）。整段文字只由这些词组成时逐词翻译，例如「MAIN RIFLE」→「主步枪」；「名称 // MAIN CANNON」这类用 `//`、`::`、` - ` 分隔的标题按段翻译。
  - `hardcoded-en.json`：`tools/scan-fvtt-labels.js` 从 foundryvtt-lancer 扫描出的写死英文快照及出处。构建会检查每段英文都有译文或标为 `null`、`{x}` 数量一致；系统升级后先运行扫描（加 `--write` 更新快照），再补译新增的条目。
- 扫描按源码推测文字，少数句子在实际页面中会被图标或标签拆开；遇到没翻译的英文，确认实际文字节点后在 `text` 中补句式或 `pieces`。2026-11-09 补扫了 Svelte 选项的 `human` 字段（掩护与命中选项）。

### 中文版面修正

中文界面启用时注入样式 `lancer-cn-ui-fix`（`UI_FIX_STYLE`）。系统的样式都在 `@layer lancer` 里，不分层的样式优先级更高，不必提高选择器权重。

- 伤害输入（`.damage-input-container`）：原本是 `min-content 12ch 1fr min-content`，类型下拉框按英文 Explosive 固定 12ch，在伤害面板的目标卡里会把数值框挤出边界（显示成「1(」）；改为下拉框 4–4.8em、数值框至少 4em。
- 命中选项（`.lancer-hit-quality-radio-label`）不换行，「未命中」不再折成两行。
- 目标名两侧的 🞂 / 🞀（U+1F782 / U+1F780，Geometric Shapes Extended）在常见中文字体里没有字形，显示成方框；文字节点中出现时换成 ▸ / ◂（`GLYPHS`）。这两个字符也出现在准度面板的总计行和扫描卡标题里，一并替换。

### 骨架插图

Foundry 按骨架英文名查找 Retrograde Minis 插图，中文名找不到。模组改按骨架 id 查找：新建或导入骨架条目时补上插图；把骨架拖到机甲上后，若机甲头像和指示物仍是系统默认图片，换成该骨架的插图（玩家自己设置的图片不替换）。车卡器的变体骨架沿用原骨架插图，没有官方插图的扩展骨架保持默认图标。

插图表 `source/fvtt/module/frame-art.json` 由系统的 `retrograde-map.ts` 生成：`node tools/build-fvtt-module.js --art ../foundryvtt-lancer/src/module/actor/retrograde-map.ts`。

### 掩护区、困难地形与危险地形

LANCER 系统没有可以摆在地图上的掩体：掩护是目标身上的状态（「掩护 - 软性 / 硬性」），命中面板读取它计入 -1 / -2，也可在面板里逐个目标手动选择。模组新增区域行为「LANCER 掩护区」（类型 `lancer-cn.cover`）与「LANCER 危险地形」（类型 `lancer-cn.dangerous`，均在 `module.json` 的 `documentTypes.RegionBehavior` 声明，显示名写进语言键 `TYPES.RegionBehavior.lancer-cn.*`）：

1. 在「区域」工具栏提供四把按格涂画的 GM 工具：**软性掩护格**（蓝色）、**硬性掩护格**（橙色）、**困难地形格**（橄榄绿）、**危险地形格**（红色），点击格子加入对应区域，再点移除，按住拖动可连续操作。Foundry 自带的区域工具在六角网格上只能吸附多边形顶点，画不出整格六边形，所以另做了这组工具：每类在每个场景合并为一个所有人可见的区域（`flags.lancer-cn.coverCells` / `flags.lancer-cn.terrainCells`）。也可以自己画任意区域，在「行为」中手动添加对应行为。
2. **掩护区**：指示物进入区域时自动获得对应掩护状态，离开时去掉；同时处在多个掩护区时取最高的掩护，停用的掩护区不计入。启用或停用行为时，区域内已有的指示物同步更新。手动给目标加的掩护状态，在它离开掩护区时会一起去掉。
3. **困难地形**：使用 Foundry v13 内建的 `modifyMovementCost` 区域行为（`difficulties: { walk: 2 }`），与 LANCER 系统的 `LancerTerrain` 移动计算直接衔接——标准步行每空间消耗 2 点移动力，飞行与「无视地形」（`ignore`）移动方式仍为每空间 1 点。
4. **危险地形**（`lancer-cn.dangerous`）：可配置失败伤害数值（默认 5）与类型（动能 / 能量 / 爆炸 / 燃烧 / 热度）。指示物移入区域（`TOKEN_MOVE_IN`）或在区域内结束回合（`TOKEN_TURN_END`）时，由触发事件的一方发送提醒聊天卡，卡上带一键「工程检定」按钮（调用 `StatRollFlow` 掷 `system.eng`）；每轮是否已触发过由 GM 与玩家按规则判断。
5. 区域事件在每个客户端都会触发，只由引发事件的用户（移动指示物的玩家或 GM）处理。

规则上掩护与攻击方向有关，掩护区只按「目标在不在区域里」判断；遇到攻击者绕到掩体背后等情况，在命中面板里手动改成无掩护即可。

### 六边形墙体

Foundry 的墙是线段，对玩家不可见，在六角网格上逐边画很费事。模组在「墙壁」工具栏加了 GM 工具「六边形墙体」（`lancerHexWall`，与掩护格工具共用 `PAINT_TOOLS` 涂画逻辑）：

- 点击格子放置一整格墙体，再点移除；按下时所在格子决定这次是放置还是移除，按住拖动对经过的格子做同样的操作。
- 指针事件在 window 的捕获阶段拦截（init 时注册）：PIXI 在画布元素上监听按下、在 document / window 上监听移动与松开，都是捕获阶段，只有 window 的捕获排在它们前面，拦在别处墙壁图层仍会收到按下，把拖动画成一道直线墙。只拦截按在画布上的左键，界面按钮和右键平移不受影响。
- 每格墙体：沿格子边缘的 6 段墙（阻挡移动，指示物无法穿过）+ 锁定的深色实心六边形图形（所有人可见，让玩家知道这里不可通过）。两者都带 `flags.lancer-cn.hexWall`（格子坐标），移除时只删这一格，先删图形再删墙。
- 格子里有墙或图形任一样就算「有墙体」，点它是移除。用 Foundry 自己的墙壁工具删掉某格的最后一段墙时（`deleteWall` 钩子），这一格的图形会一起删掉。
- 默认不阻挡视线与光照；世界设置「六边形墙体阻挡视线」打开后，新放置的墙体也阻挡视线与光照。墙体不提供掩护。
- 使用 `canvas.grid.getOffset / getVertices`，方形网格也能用（4 段墙），无网格场景会提示不能放置。

### 指示物名字与飘字

- **名字**：世界设置「指示物显示名字」（默认「始终显示」，另有「鼠标悬停时显示」「不改」）。新放上地图的指示物在 `preCreateToken` 时设好 Foundry 的「显示名称」；第一次启用模组、或 GM 改这项设置时，由在线的 GM 把各场景里已放好的指示物一起改（`applyTokenNames`）。「始终显示」时玩家也看得到 NPC 的名字，不想透露时选「悬停时」，或单独改该指示物。
- **伤害 / 热度飘字**：LANCER 自带「浮动伤害数字」：角色的 HP、过载护盾、燃烧、热度、结构、压力、维修变化时，由改动的客户端在指示物上飘字，并经系统 socket 让其他人也显示。这是每位玩家各自的设置，默认关闭；模组在每个客户端第一次载入时替玩家打开一次（隐藏设置 `floatingNumbersOn` 记录），之后按各人自己的设置。文字已在「写死的英文」里译成「-5 HP」「+2 热度」。
- **状态飘字**：Foundry 加上 / 去掉状态（ActiveEffect 的 `_displayScrollingStatus`）时飘出「+(名称)」，中文界面下改成更大、带颜色的「+ 缓慢」（黄色）/「- 缓慢」（灰色）。命中后施加状态的按钮、标记 HUD、掩护区都会触发。
- 飘字只在改动发生时、指示物所在场景正在显示的客户端上出现；隐藏的指示物不显示状态飘字。

### 基础动作与对抗检定

LANCER 的机甲表、NPC 表与驾驶员表只有不带说明的「基础攻击」「科技攻击」按钮（机甲表另带稳住阵脚与超限，驾驶员表只有基础攻击与掷伤害）。模组在系统「战斗工具」卡片（机甲在「装配」页，NPC 在主页，驾驶员在「驾驶员」页；以其按钮栏 `.lancer-flow-button-grid` 里的「基础攻击」按钮定位）下方加一张双层「基础动作」卡片（`BASIC_ACTIONS`、`beginBasicAction`），并内置通用对抗检定引擎（`createContestCard`、`respondToContest`：发起方先掷骰出卡，被对抗方点击应战按钮掷骰，平局由发起方胜出，处于「晕眩」的机甲在机体 / 敏捷对抗检定中自动失败）。

实现细节：

- `Flow.begin(data)` 会用 `data` 取代整个状态，并把它当作各步骤的选项；初始化步骤里标题取 `options?.title ?? "BASIC ATTACK"`，所以模组把标题、说明和入侵标记放进 `begin(data)`。
- 攻击卡的 `attackData` 不带标题。模组在发起时记下动作，`preCreateChatMessage` 给同一攻击者、不带物品的攻击卡加 `flags.lancer-cn.basicAction`，状态、擒拿控场与权宜攻击伤害据此判断。
- 不扣动作栏的动作次数（系统的基础攻击按钮也不扣）。

### 受限次数

- **掷骰式受限**：Foundry 用 `parseInt` 读受限值，「1d6+2」读成 1。内容包里只有原型武器 I / II（1d6+2）、III（2d6）是这种写法。模组包装物品的 `prepareFinalAttributes`：受限值是骰子式时，上限 = 掷出的结果（`flags.lancer-cn.limitedRoll`）+ 机甲的受限加值，没掷过为 0。物品「USES」格子旁加「掷 1d6+2」按钮；`lancer.postFlow.FullRepairFlow` 成功后重掷。上限为 0 时系统视为不受限，不会阻止攻击。
- **文字里的受限**：Foundry 只按受限标签计数，骨架没有次数栏，系统动作说明里写的「（受限 1）」也不计。模组在机甲表「装配」页列出「受限次数」卡片（`textCounters`）：扫描机甲的骨架核心系统、特性、各物品的效果与动作说明，以及驾驶员已解锁的天赋等级，找出「受限 N」（物品已有受限标签的跳过；同一物品重复写的同一个值合并）。次数存在机甲的 `flags.lancer-cn.counters`，点格子扣减 / 恢复，全面维修后回满。
  - 天赋说明中括号里的「（0 SP、受限6……）」是天赋所给装备的摘要，装备本身是单独的物品，不计。
  - 「受限1/回合」这类写法不计。例如工兵天赋 II 的文字「爆破者工具箱 0SP，4 受限」后接「1/回合」，是原书标题行（0 SP、受限 4）的排法，爆破者工具箱本身是带受限 4 标签的物品，由系统计数。
  - 2026-11-11 两个内容包里会出现计数器的：孙子「霎间锚点」、哈布斯堡「E-R-桥塔」、八角「建筑项目」、“洞察”原型思维体、“诡术师”干扰套组。

### 说明里的骰子

LANCER 的物品表与聊天卡直接输出说明 HTML，不经 `enrichHTML`，内联掷骰 `[[/r 1d6]]` 不会变成链接。模组在 `.effect-text`、`.desc-text` 里把「1d6」「1d6+2」「d20」等换成带骰子图标的链接（`linkDice`，MutationObserver 处理之后新出现的内容）；点击时以所在物品的拥有者、聊天消息的发言者或所在角色表的角色名义掷骰，标题为物品名。不处理链接、按钮、输入框、编辑区和系统的掷骰结果；「D288」这类编号不算骰子。

### 攻击时选目标

LANCER 的攻击、科技攻击和掷伤害都用玩家当前在 Foundry 里锁定的目标。Foundry 的锁定方式（悬停按 T、右键菜单、切换「选择目标」工具）对玩家不顺手，上一次的目标也会一直留着。模组加了目标面板：

- **开关时机**：用系统公开的 flow 钩子 `lancer.preFlow.<类名>` / `lancer.postFlow.<类名>`（`BasicAttackFlow`、`WeaponAttackFlow`、`TechAttackFlow`、`DamageRollFlow`；系统构建保留类名，`docs/flow_api.md` 有说明）。攻击开始时打开，结束或取消时关闭。从攻击卡掷伤害时目标已按命中结果锁定，不弹面板。
- **列表**：同场景、自己看得见的指示物（GM 看全部），按攻击者的立场分为敌方 / 中立 / 友方，组内按距离排序。距离取双方所占格子（`getOccupiedGridSpaceOffsets`）之间最近的一格，用 `canvas.grid.measurePath` 计算。射程取当前武器模式的射程 / 威胁 / 投掷 / 线形 / 锥形 / 爆发的最大值，科技攻击用感应。只作提示，不阻止选择。
- **点地图锁定**：面板开着时，左键点指示物（攻击者自己的除外，按住修饰键时不接管）就是锁定 / 取消锁定。与六边形墙体一样在 window 捕获阶段拦截，图层收不到这次点击。
- **清除旧目标**：攻击成功结束时记下锁定的指示物；下一次攻击开始时，若锁定的仍是这几个（之后没改过）就先清掉，列表里给它们标「上次」。之后若一个目标都没有、射程内恰好一个敌人，自动锁定它。
- **设置**（客户端，默认开启）：「攻击时显示目标选择面板」「开始新攻击时清除上一次的目标」「射程内只有一个敌人时自动选中」。
- LANCER 的准度面板会随 `targetToken` 钩子刷新，所以面板里改目标会立刻反映到准度面板。

### 战斗自动化：状态、豁免、非攻击伤害、跨权限结算与流程补完

LANCER 系统没有实装命中效果状态施加、强迫豁免联动、非攻击卡掷伤害、跨权限伤害结算以及部分流程步骤（如机甲「稳住阵脚」清除状况、NPC「致命」暴击加伤、1 压力上限 NPC 过热扣减热度上限）。模组 1.10.0 在不改系统本体的前提下补齐上述链路，并提供四个世界设置开关（均默认开启：`autoApplyStatus`、`crossPermDamage`、`autoDangerZone`、`turnEndPrompt`）：

- **自动挂异常、消除锁定与「↩ 撤销状态」**（`classifyAttackCard`、`selfStatusesIn`、`onCreateChatMessage`、`undoAppliedStatuses`）：
  - 严格区分无条件命中效果（`autoHitStatuses`）、无条件会心效果（`autoCritStatuses`）与豁免前置效果（归入 `saves[].failStatuses`）：攻击命中 / 会心命中后，只自动挂无豁免、无可选条件的状态，并自动消除本次消耗的目标「锁定」（解决系统 `attack.ts` 中非 GM 玩家无法清除敌方锁定的问题）。
  - 非攻击激活 / 系统卡识别明确的自身增益与抗性（全伤害抗性、五种单项抗性、隐形、无形、匿迹、飞行、支援）并自动挂给自己；针对盟友或有条件选择的增益列为手动按钮，否定受益与部署物隐形等写法不误判。
  - 每次自动挂状态都把本次**新增**的状态记入 `flags.lancer-cn.appliedStatuses`，并在聊天卡下方渲染「已自动施加：……」与**「↩ 撤销状态」**按钮——点击只移除本卡新挂上的状态，不会误删目标原本就有的状态。带条件的状态仍保留手动「命中效果 · 施加」按钮，无权限时经模组 socket 请在线 GM 执行。

Foundry 的内容包导入只按骨架生成牌照（并且只新建、不更新），也不导入厂商。模组在「配置设置 → 模组设置 → LANCER 中文」中提供 GM 按钮「导入车卡器资料」，导入两个中文内容包后运行，可以重复运行：

- **专业牌照**：在 LANCER 的驾驶员物品合集包（`world.pilot-items`）建立 21 张牌照条目（lid `lic_<专业牌照 id>`，key 为专业牌照 id，厂商为所属厂商，默认牌照等级为该牌照的等级）。专业牌照装备在扩展内容包中的牌照字段就是这个 id，牌照表会按等级列出它们。Foundry 不检查取得条件（前置牌照、计费），由 GM 把关。
- **骨架牌照改名**：英文数据先导入时，骨架牌照一直是英文名；按骨架 id 找到合集包中的骨架，把牌照名改为骨架的中文名。
- **日志合集包「车卡器资料」**（`world.lancer-cn-reference`）：「专业牌照」（规则说明 + 21 页，含厂商、等级、说明和链接到合集包的解锁装备）、「扩展厂商」（C&H、K/KCA、PI-OF 的说明、骨架与专业牌照）。核心五家厂商在车卡器中没有说明文字，不生成页面。重复运行时，模组生成的日志会被替换。

数据由 `tools/build-fvtt-module.js` 从 `assets/js/data.js` 生成，专业牌照的规则说明在 `source/fvtt/module/professional-rules.json`。

## 内容包的内容

### 核心规则书

Foundry 核心数据中的 424 个条目全部覆盖，另新增 7 个车卡器有、Foundry 数据没有的标签。

- 以 Foundry 使用的 lancer-data 3.1.7 为底，保留其主动效果、动作、协同效果等自动化结构。
- 名称和说明来自车卡器（v3.5 译名、规则站与自译中文、风味文本）。天赋等级里的动作按车卡器中文说明块换上中文名称、触发和说明。
- 数值只采用车卡器有意改过的部分（data.js 与车卡器 lancer-data 副本不同之处）。车卡器的 lancer-data 副本比 3.1.7 旧，其余数值沿用 Foundry 的，避免把新版勘误改回去。2026-11-07 构建时没有这类数值差异。
- 状态与状况：Foundry 的 15 个状态与状况，名称和说明取自车卡器术语库（依 v3.5；Down and Out 为「昏迷」），简述另写在 `source/fvtt/statuses-zh.json`。保留官方的 icon、类型，导入时覆盖英文条目；晕眩的数值效果由 Foundry 照常生成。
- 不导出：背景（Foundry 的内容包导入不支持）、预备资源。

### 扩展内容

- 覆盖官方条目：以官方补充书数据为底，换成车卡器的中文文本和数值（108 个）。
- 新增条目：车卡器独有的骨架、装备、天赋与核心奖励（哈勃、法罗斯、米切尔、K/KCA、PI-OF、C&H 等），以及改装附带的武器（323 个）。

官方有、车卡器没有对应中文的文字（协同效果、部分动作说明、弹药与数据组名称、核心系统风味文本）由 `source/fvtt/zh-overrides*.json` 补译。2026-11-07 两个包都已没有残留英文；以后官方数据或车卡器内容变动时，新出现的英文会列在核对表与待译清单中。

### NPC

Foundry 自带的官方数据里只有补充书的 NPC：Dustgrave 的 3 个 NPC 模板（恐怖体、工业机甲、特战队员）与 31 个 NPC 特性，SotW 的 1 个 NPC 特性。核心规则书的 NPC 职业名册不在 Massif 公开的 lancer-data 中，Foundry 也不自带；两个中文内容包改用车卡器「NPC 构筑」的数据补上（见本节后半）。

- 扩展包收录这 35 个条目：以官方记录为底（快照在 `source/fvtt/official/<补充书>/npc_*.json`），名称、效果、命中效果等文字换成 `source/fvtt/zh-npc.json`；类型、武器类型、伤害、射程、标签、模板的特性列表保持官方原值。特性的来源模板名（显示在特性标题上）改为模板的中文名。
- `zh-npc.json` 由 GPT 依 `node tools/export-npc-todo.js` 导出的 `dist/fvtt/zh-npc.todo.json` 翻译，2026-11-09 核对：70 处全部齐全，HTML 与数字与原文一致，状态与术语符合车卡器用法；改了一处（虚空撕裂补回「自由空间」）。
- 导入扩展包后，把 NPC 模板拖到 NPC 角色上即可使用；已建立的 NPC 角色身上的特性不会自动更新。

车卡器「NPC 构筑」的职业、模板与特性也随内容包导出（2026-11-09，`build-lcp.js` 的 `buildBuilderNpcs`，数据取自 `assets/js/npc-classes.js`）：

| 内容包 | 职业 | 模板 | 特性 |
|---|---|---|---|
| 核心包 | 33（核心规则书 30 个机甲职业 + 人类、班组、怪形） | 12 | 409 |
| 扩展包 | 52（官方模组 7 + 第三方书 45） | 10 | 612 |

- 尘墓的 3 个模板沿用上面的官方数据，不重复导出；车卡器导出的 NPC 用的也是同一组官方 id。
- 写成 LCP 的 `npc_classes` / `npc_templates` / `npc_features` 格式：三个层级的数值是数组，层级标签值写成 `{a/b/c}`，Foundry 没有的关键词（鲜血 2+、召集、装置 5 等）写在效果开头。
- Foundry 的特性加成只有一组数值；按层级不同的加成（人类「老兵」+2/+4/+6 HP）取 T1，原文在效果里。

### 动作按钮

Foundry 只给结构化的「动作」显示按钮：点了会发聊天卡、扣动作追踪，反应显示「使用反应」，入侵自动进行科技攻击。官方条目自带动作；车卡器新增的扩展条目，构建时按两种来源补上（覆盖官方的条目保留官方动作）：

- **说明块**：车卡器里写成「名称 + 类型」说明块、类型含动作词的（入侵、反应、协定、快速动作等）直接转成动作，并从效果文字中移除，频率（1/轮）与自身热度一起带上。共 15 个，主要是 C&H、伊芙利特、白星等的入侵选项。
- **正文**：「以一个快速动作……」「可用反应……」这类写在正文里的动作，由 `node tools/draft-ext-actions.js` 按句式生成草稿，写入 `source/fvtt/ext-actions.json` 后人工核对（名称、类型、频率、触发、说明；不该加的写成 `[]`）。主语是别人的动作（「他们可用快速动作移除」）与否定写法（「无法使用反应」）不生成。重新运行 `--write` 只补新出现的条目，不覆盖人工修改。

生成结果列在[扩展包核对表](FVTT-LCP-AUDIT.md)「自动生成的动作按钮」。武器本身一直可以点击攻击，核心系统也一直有激活按钮；有条件的加值（飞行时 +1 准度等）Foundry 无法自动套用，仍保留为文字。Foundry 原生的动作按钮本身不带掷伤害流程（系统中为 TODO），启用 `lancer-cn` 1.10.0+ 后会按卡片文字识别角色伤害并补上「掷伤害」按钮。

**动作推断复核（2026-11-09）**：用户另行复核了正文推断的动作（问题清单在用户本机，未入库），据此修正 `ext-actions.json`：

- 9 处明确不符：频率挂错动作（蝉鸣叨叨的 1/场景是每名目标的限制、地震脉冲场的 1/轮属于震碎地形、破坏者无人机的 1/轮属于骑乘选项、伊芙利特的 1/轮属于消耗标记）；拒签投降书的协定是停止而非启动；跨域镀层自毁反应的触发是「你被命中」；鸟翼蝶丝之舞的触发；爆破者工具箱只保留「引爆远程地雷」；八角的部署与藤蔓传送分开。

- 顺带补了原文写明的两个动作：阿格里帕包骡无人机展开 / 收起弹道板（协定）、爆炸锁链引爆地雷（快速动作）。

### 部署物

说明文字里写了数值、但没有结构化部署物的 7 个条目，照原文转录到 `source/fvtt/ext-deployables.json`，导入后可从系统 / 核心系统上拖出指示物：可展开桥梁、休克桥塔、破坏者无人机、盾牌阵列无人机、夜莺无人机、火蜥蜴的矿渣爆爆（一次 3 枚）、网斗士的锚点装置（一次 3 个）。原文没写的数值（如休克桥塔的电子防御、桥梁的大小）不补，Foundry 用默认值，说明末尾提示 GM 手动调整。冰块、地雷、信标这类由效果临时产生的地形或物品仍保留为文字。

### 改装附带的武器

Foundry 的武器改装不能带武器数据，安装改装也不会加入内建物品。车卡器里带附加武器数据的改装（目前只有下挂式冲击器），扩展包另导出一件「附带武器」（`mw_<改装 id>_data`，同牌照、0 SP、不受其他改装与核心奖励影响），安装改装后拖到机甲上即可直接攻击。其余扩展改装的效果依赖武器尺寸、相邻角色数或属于替代攻击 / 重骰，无法写成 Foundry 的固定附加伤害或标签，仍为文字。

### 需要 GM 手动处理的规则

Foundry 不知道车卡器的特殊规则，相关条目的说明末尾有「【车卡器说明】」段落：

- 变体骨架与原骨架互斥。HP 不加毅力的帝王蝶由 Foundry 自动扣除毅力（系统对官方 id `mf_emperor` 的特殊处理），不需要手动处理。
- 康格多需要核心奖励「康格多底盘」，不占牌照。
- 专业牌照装备（Foundry 不检查专业牌照的取得条件）、天赋装备（标为不需要牌照）。
- 无人机武器在 Foundry 中按主武器挂载记录，机甲本身不能使用。
- 多类型武器、可选数据组、双改装武器、标签叠加的改装。
- 私人家教、招牌动作等由车卡器自动计算的核心奖励。
- 部署物上「与部署者相同」的回避、电子防御（Foundry 先用默认值）。
