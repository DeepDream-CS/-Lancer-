# NPC 资料

## NPC 库：原书参考资料

来自用户提供的官方核心规则与扩展、官方模组、第三方扩展与模组三个目录，共 24 本 PDF。`catalog.json` 记录每个参考页的来源及 PDF 页序。原书页面在 `assets/npc/`，文字索引在 `assets/js/npc-data.js`。

NPC 库是原书浏览与搜索：保留数值表、基本与可选系统的原始版面，不对提取文字中的跨列数字进行自动推算。全文检索包括附录外特殊单位、战斗配装及上下文；普通剧情 NPC 提及不自动认定为独立战斗职业。重复收录按书籍分别保留。

## NPC 构筑：结构化数据（2026-11-09）

| 文件 | 内容 | 解析工具 |
|---|---|---|
| `core-npcs.json` | 核心规则书 v3.5（PDF 第 278–325 页）：33 个职业、12 个模板、409 个特性 | `tools/parse-npc-core.js` |
| `books-npcs.json` | 官方模组与第三方书：52 个职业、10 个模板、612 个特性 | `tools/parse-npc-books.js` |

- 两个工具都从 `assets/js/npc-data.js` 的原书文字解析，不另外转录，共用同一套解析规则。
- `node tools/build-npc-classes.js` 把这两份数据和 Foundry 官方《尘墓》的 3 个 NPC 模板（英文数据在 `source/fvtt/official/dustgrave/`，中文在 `source/fvtt/zh-npc.json`）合并，生成 `assets/js/npc-classes.js`（生成文件，不要手改）。
- `node tools/build-lcp.js` 再把职业、模板和特性写进两个 Foundry 中文内容包：核心规则书进核心包，其他书进扩展包，尘墓沿用官方数据。

**修改方法**：改解析工具里的规则或补丁，依次运行：

```bash
node tools/parse-npc-core.js --write    # 或 parse-npc-books.js --write
node tools/build-npc-classes.js
node tools/build-lcp.js
node tools/test-npc-builder.js
node tools/test-lcp.js
```

测试会检查 JSON 与解析结果一致，所以不要直接手改两个 JSON。`--text` 逐条列出全部文字，用来和原书核对；`parse-npc-books.js --empty` 列出没有文字的特性及其原书上下文，方便找出效果排错位置的情况。内容包数据变了要提高 `tools/build-lcp.js` 里 `PACKS` 的版本号。

### 录入原则

- **原文照录**：特性名称、类型行、效果、触发、命中效果都保留原书文字，包括原书的错字和用词，例如「引导」「智能」「雷射」。只做两件事：
  - 分段：区分基础与可选，把名称和类型行分开，把写在名称之前的「触发 / 效果」归给对应的反应。
  - 数值提取：三个层级的数值、攻击加值、准度 / 难度、射程与伤害。
- **由其他特性授予的反应**（如压制给的「活靶子」、覆盖火力给的「逮住你了」）不单列，并入授予它的特性，写成「【名称】（反应）触发：… 效果：…」。
- **大小**写成「1/2 或 1」「1 或 2」「1~3」的，数值取第一个，原文保存在 `size_note`，页面上会显示。
- **Foundry 没有的关键词**（「鲜血 2+」「召集」「装置 5」「能源 6」等）作为关键词显示，导出到 Foundry 时写在效果开头。
- **模板的数值加成**只填原文写明的数字，写在各解析工具的 `STAT_PATCHES` 里：
  - 核心：强化 +1 结构 / +1 压力（超体 +3）；韧性 +5 HP；精英、超体每轮多一个回合；低等兵 HP 设为 1；飞船大小 4；阿耳戈斯装甲设为 6 装甲；人类「老兵」每层级 +2/+4/+6 HP；人类与班组的「披甲」按 +1 装甲计（原文 +1~2，需要时在页面上手动加减）。
  - 其他书：列车、合约杀手的额外结构 / 压力和每轮两个回合；捍卫者强化；铲土机重装机体 +5 HP；动员兵战斗盾 +2 HP；十字军塔盾 +1 装甲（原文：只要该武器未被摧毁）。
- **人类**的「定制」原文是列表，不是特性标题：三种武器（选其一）和老兵、披甲都作为可选项，选择规则写在 `custom_note`。

### 其他书的版面问题与处理

这些书的提取文字比核心规则书乱，各书的处理逐条写在 `parse-npc-books.js` 的 `BOOKS` 与 `FEATURE_PATCHES` 里，可以追溯：

- 续页下半的小说、通讯记录和题词：用 `cut` 切掉。涉及《苏丹》大部分续页，以及《浴金焰》两处。
- 系统的效果文字排在名称前面：用 `moves` 移回。多见于协定类系统，例如《塞壬之歌》暴风雨的可选系统、《卡斯特与帕勒克》拦截机、《天堂末班车》警卫。
- 选项清单：主战坦克「必须选择一门主炮和一件辅助武器」，比蒙巨兽「辅助节点」的节点类型。原书列在基础系统里，这里改为可选项，供挑选。
- 暴风雨的「类别 I / II / III」：并入「气象灰浴」。
- 《冷核圆形竞技场》：「特殊规则」段作为一条基础特征；多模式武器（如火神卡宾枪的远镜 / 满磁 / 刺刀）只能识别第一种模式的数值，其余模式保留在效果文字里。

## 已确认

**甲胄骑兵「撞锤加农炮」、马蜂「巫术导弹」**（2026-11-09，用户对照英文核心规则书第 296、303 页）：数值确实是准度，不是攻击加值，目前的录入正确。英文原书在类型行的数值后面带准度图标，撞锤加农炮还另外写明攻击加值 +0。

| 武器 | 攻击加值 | 层级 I / II / III 的准度 |
|---|---|---|
| 甲胄骑兵「撞锤加农炮」Ram Cannon | +0 | +1 / +2 / +3 |
| 马蜂「巫术导弹」HEX Missiles | +0 | +1 / +2 / +3 |

所以层级 III 攻击时是掷 1d20，再掷 3 颗准度骰取最高一颗加入结果，而不是直接 +3。准度仍会与难度抵消。
